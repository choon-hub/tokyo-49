# 東京区市制覇アプリ「tokyo-49」 要件定義書（ドラフト v0.2）

最終更新: 2026-10-12

## 1. 概要

### 1.1 目的
東京都内の **23区 + 26市（計49区市）** を制覇することを目的に、訪れた場所を記録し、訪問済みの区市を可視化する。

### 1.2 前提・方針
| 項目 | 内容 |
|---|---|
| アプリ名 / slug | tokyo-49 |
| 対象端末 | Android スマホ（最低サポートOSは指定なし。Expo SDK の既定値に従う） |
| 画面の向き | **縦固定** |
| 言語 | **日本語のみ**（多言語対応なし） |
| テーマ | **ライト／ダーク両対応**（端末のシステム設定に追従） |
| 技術スタック | Expo Router + React Native + SQLite（expo-sqlite） |
| 運用コスト | **0円**（課金サービス・外部API依存なし） |
| 配布 | 個人利用（APK 直インストール）想定。Play ストア公開は未定 |
| 通信 | **完全オフラインで動作**（サーバーなし） |
| 訪問の記録方法 | ユーザーの**自己申告（手入力）**のみ。位置情報による自動記録は行わない |

### 1.3 スコープ外（現時点）
- 町・村・島しょ部（49区市のみが対象）
- 写真・評価の記録
- 初制覇時の演出
- 位置情報の自動取得
- Google Maps API / 国土地理院 API 連携（v2 以降で再検討）
- 区市未確定の施設名の下書き保存（Q15で非対応に確定）
- 全訪問履歴を横断して見る画面（区市ごとのボトムシートのみ）
- 区／市部別の制覇数、訪問回数ランキングなどの統計表示（制覇数 / 49 のみ）
- 検索の部分一致、表記ゆれ（ヶ／ケ など）の正規化
- 保存・削除時の確認ダイアログ、削除の取り消し（Undo）
- 自動バックアップ等のデータ消失対策（自己責任）

## 2. 機能要件

### 2.1 訪問場所の入力
1. 入力欄に自由テキストを入力できる（漢字・ひらがな・カタカナ、「駅」付きも可）。
2. 入力に応じて、駅名・町域名の辞書から**前方一致のみ**で候補を表示する（部分一致は行わない）。
   - 表示形式: `上野駅（台東区）` / `西新宿（新宿区）`
   - 駅を町域より先に並べる。
   - 候補は最大30件表示し、これを超える場合は末尾に **「他N件」** を表示して入力の絞り込みを促す（N = 全ヒット件数 − 30）。
3. 候補を選ぶと区市が確定する。
4. 辞書にヒットしない入力（施設名など）は、入力文字列を場所名として保持し、**区市を手動選択**させる。
5. 区市を直接選択する導線（特定スキップ）を常に用意する。区市のみを選んだ場合、場所名には区市名を自動入力する（Q16）。
6. 辞書にない入力（都外の駅など）は「候補なし」と表示し、区市の直接選択へ誘導する（都外であることの明示はしない）。
7. 訪問日は**初期値＝今日（端末のローカル日付）**。過去日・未来日とも自由に指定できる。必須項目で、日付不明は不可。
8. 保存は確認ダイアログなしで即時反映する。

### 2.2 区市の特定ルール
| ケース | 扱い |
|---|---|
| 駅名 | 駅データの代表点から区市を判定し、辞書に格納済み |
| 町域名 | 郵便番号データから区市を紐付け済み |
| 複数区市に同名の町域がある（例: 本町） | 区市名を併記した候補から選ばせる |
| 区境をまたぐ駅（例: 新宿駅） | **自動で1つに確定**（`overrides.json` で固定） |
| 事業者違いの同名駅（新宿＝JR・京王・小田急ほか） | 同一区市なら1件に統合 |
| 駅名と所在区が一致しない駅（例: 目黒駅＝品川区） | 駅データの所在地を正とする |
| 施設名 | 辞書では引かず、自由入力＋区市の手動選択 |

### 2.3 訪問履歴の記録
- 訪問は **1訪問 = 1行**で記録する。同じ場所を何度でも追記できる。
- 項目: 場所名、区市、訪問日、メモ（任意）、入力経路（駅 / 町域 / 手動）
- 訪問済み区市は**履歴から導出**する（フラグは別に持たない）。履歴を全削除すれば未訪問に戻る。
- 履歴の閲覧・編集・削除は、**区市のボトムシート内**で行う（全履歴の横断画面は設けない）。
- 削除は確認ダイアログなしで即時実行する（取り消し不可）。
- 編集できる項目は場所名・訪問日・メモ。区市と入力経路は変更不可（誤りは削除して再登録）（Q20・暫定）。

### 2.4 制覇状況の可視化
**地図の塗り分け**
- 49区市のポリゴン（簡略化した SVG パス）を描画し、訪問済みを塗り分ける（最小実装は2値。訪問回数による濃淡は拡張案）。
- ピンチズーム・パンに対応する。**市部の西側（奥多摩方面など）まで**パンで到達できること。パンは地図範囲内に制限する。
- **ズームのリセットボタン**を常設し、タップで初期表示（23区ズーム）に戻す。
- 区市をタップすると**ボトムシート**を開く。
  - 区市名、過去の訪問履歴（場所名・訪問日・メモ）、各履歴の編集・削除
  - 追記ボタン（区市は確定済みのため、場所名・日付・メモのみ入力）
  - 未訪問の区市をタップした場合も、同じシートから追記できる。
- 配色は**ライト／ダークそれぞれに専用パレット**を定義する（訪問済み・未訪問・境界線・背景）。どちらでも訪問済みと未訪問が明確に区別できるコントラストを確保する。

**一覧表示**
- 49区市のチェックリストをタブで併設する（23区は小さく地図でのタップが難しいため、保険を兼ねる）。
- 一覧からも同じボトムシートを開ける。
- 制覇数 / 49 を表示する（区／市部の内訳表示はしない）。

### 2.5 データのエクスポート／インポート
- 機種変更の引き継ぎ用に **JSON のエクスポート／インポート**を備える。
- 通常の UI には出さず、**設定画面の奥または隠し導線**に置く（UX 優先）。
- エクスポート形式（辞書は同梱のため対象外）:

```json
{
  "version": 1,
  "exportedAt": "2026-10-12T08:00:00Z",
  "visits": [
    { "placeName": "西新宿", "municipalityCode": "13104", "source": "town",
      "refId": 123, "visitedOn": "2026-10-12", "memo": null,
      "createdAt": "2026-10-12T08:00:00Z", "updatedAt": "2026-10-12T08:00:00Z" }
  ]
}
```

- **インポート時の検証**（1件でも不正なら**ファイル全体を拒否**し、最初の不正箇所を表示する。DB は一切変更しない）:
  - `version` が 1 であること
  - `visits` が配列で、各要素の必須項目（placeName / municipalityCode / source / visitedOn）が揃っていること
  - `municipalityCode` が49区市のコードに含まれること
  - `source` が `station` / `town` / `manual` のいずれかであること
  - `visitedOn` が実在する `YYYY-MM-DD` であること
  - `memo` が文字列または null であること
- 検証通過後、**マージ（追加のみ）か上書きか**を確認ダイアログで選ばせる（破壊的操作のため、この確認は残す）。
  - マージ: 重複判定キー **（placeName + municipalityCode + visitedOn）** が既存と一致する行はスキップする。
  - 上書き: 既存の visits を全削除してから取り込む。
  - いずれも**1トランザクション**で実行し、失敗時はロールバックする。
- `refId` は参考値として保持するのみ。インポート先の辞書との整合は取らない。

## 4. 区市の特定方式

**結論: 事前辞書（同梱）方式を採用。Google Maps API は使わない。**

| 層 | 手段 | コスト |
|---|---|---|
| ① 直接選択 | 49区市のマスタから選ぶ | 0 |
| ② 駅辞書 | 駅名・読み → 区市コード | 0 |
| ③ 町域辞書 | 町域名・読み → 区市コード | 0 |
| ④ 施設名 | 自由入力 + 区市の手動選択 | 0 |

**不採用の理由**
- Google Maps Platform: 課金アカウントが必須で、無料運用の方針と合わない。
- 国土地理院 API: 得意なのは住所・町域で、施設名には効かない。町域は辞書で賄えるため効果が薄い（v2 以降で保留）。

### 4.1 辞書データの生成（ビルド時に1回実行）
| データ | 出典 | 用途 |
|---|---|---|
| 駅 | 国土数値情報 N02 | 駅名と代表点 |
| 行政区域 | 国土数値情報 N03 | point-in-polygon による区市判定、地図ポリゴンの元データ |
| 町域 | 日本郵便 KEN_ALL | 町域名・読み・区市 |
| 駅の読み | 別データで補完（候補: 駅データ.jp 等） | N02 に読みが無いため。**ライセンスと収録項目は要確認** |

**処理上の注意**
- KEN_ALL は「以下に掲載がない場合」などのノイズ行を除去し、町域名＋区市コードで重複排除する。
- 境界駅の誤判定は `overrides.json`（駅名 → 区市コード）で手動パッチする。
- N03 は mapshaper 等で簡略化し、画面座標に変換済みの SVG パス JSON を生成して同梱する（島しょ部は除外）。

### 4.2 成果物と同梱方式
ビルドスクリプトは次の3点を出力する。
1. **`dict.db`**: 事前ビルド済みの辞書DB（`municipalities` / `stations` / `towns` / `meta`）。アセットとして APK に同梱する。
2. **`municipalities` 定数**（TS/JSON）: 49区市のマスタ。地図・一覧・制覇判定・インポート検証で使う。
3. **地図パス JSON**: 49区市の SVG パス。

**辞書の更新**: `dict.db` に `meta.dict_version` を持たせ、アプリ起動時に同梱版が端末内の版より新しければ `dict.db` を**丸ごと上書きコピー**する。`user.db` には一切触れない。

## 5. データモデル（expo-sqlite）

DB は2ファイルに分ける。

| ファイル | 内容 | 性質 |
|---|---|---|
| `dict.db` | 辞書（municipalities / stations / towns / meta） | 読み取り専用。アプリ更新で差し替え |
| `user.db` | 訪問履歴（visits） | 読み書き。ユーザーデータ |

ファイルが別のため、`visits.municipality_code` に**外部キー制約は張らない**。値の妥当性は49区市の定数マスタで検証する。

### 5.1 dict.db
```sql
CREATE TABLE meta (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL         -- 例: key='dict_version'
);

CREATE TABLE municipalities (
  code TEXT PRIMARY KEY,      -- '13101' など（JIS）
  name TEXT NOT NULL,
  kana TEXT NOT NULL,
  type TEXT NOT NULL CHECK (type IN ('ward','city'))
);

CREATE TABLE stations (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  kana TEXT NOT NULL,
  municipality_code TEXT NOT NULL REFERENCES municipalities(code),
  lines TEXT                  -- 表示用。例: 'JR山手線,銀座線'
);
CREATE INDEX idx_stations_name ON stations(name);
CREATE INDEX idx_stations_kana ON stations(kana);

CREATE TABLE towns (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  kana TEXT NOT NULL,
  municipality_code TEXT NOT NULL REFERENCES municipalities(code)
);
CREATE INDEX idx_towns_name ON towns(name);
CREATE INDEX idx_towns_kana ON towns(kana);
```

### 5.2 user.db
```sql
CREATE TABLE visits (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  place_name TEXT NOT NULL,                -- 駅名・町域名・施設名（自由入力）・区市名（直接選択時）
  municipality_code TEXT NOT NULL,         -- 49区市のコード。FKなし（アプリ側で検証）
  source TEXT NOT NULL CHECK (source IN ('station','town','manual')),
  ref_id INTEGER,                          -- 辞書の id。参考値のみ。整合は municipality_code と place_name に依存
  visited_on TEXT NOT NULL,                -- 'YYYY-MM-DD'（未来日可）
  memo TEXT,
  created_at TEXT NOT NULL,                -- ISO 8601 (UTC)
  updated_at TEXT NOT NULL                 -- ISO 8601 (UTC)
);
CREATE INDEX idx_visits_muni ON visits(municipality_code);
```

**`ref_id` の扱い**: 辞書の再生成で ID が変わり得るため、`ref_id` は表示や再検索の補助にのみ使う。参照整合には使わない。

**制覇判定（導出クエリ）**: `user.db` で集計し、アプリ側で49区市マスタと突き合わせる（件数0の区市は未訪問）。
```sql
SELECT municipality_code, COUNT(*) AS visit_count
FROM visits
GROUP BY municipality_code;   -- 行がある区市が制覇済み
```

## 6. 候補検索の仕様

検索は `dict.db` に対して行う。

**入力の正規化**: NFKC 正規化 → カタカナをひらがなに変換 → 末尾の「駅」を除去 → trim

```ts
const toHira = (s: string) =>
  s.normalize('NFKC')
   .replace(/[ァ-ヶ]/g, c => String.fromCharCode(c.charCodeAt(0) - 0x60))
   .replace(/駅$/, '').trim();
```

表記ゆれ（ヶ／ケ、旧字体など）の追加正規化は行わない。`LIKE` のワイルドカード（`%` `_`）は入力側でエスケープし、`ESCAPE '!'` を指定する。

**検索**: 駅・町域を UNION ALL で1本にまとめ、名前または読みの**前方一致**で最大30件。駅を先に並べる（`source` で並べ替え）。

```sql
SELECT 'station' AS source, s.id, s.name, m.code AS municipalityCode, m.name AS municipality
  FROM stations s JOIN municipalities m ON m.code = s.municipality_code
 WHERE s.name LIKE ?1 || '%' ESCAPE '!' OR s.kana LIKE ?1 || '%' ESCAPE '!'
UNION ALL
SELECT 'town', t.id, t.name, m.code, m.name
  FROM towns t JOIN municipalities m ON m.code = t.municipality_code
 WHERE t.name LIKE ?1 || '%' ESCAPE '!' OR t.kana LIKE ?1 || '%' ESCAPE '!'
ORDER BY source, 3 LIMIT 30;
```

**「他N件」用の件数取得**: 上記と同じ WHERE 条件で `COUNT(*)` する別クエリを実行し、`総数 − 30` が1以上のときだけ「他N件」を表示する。

## 8. 実装タスクの目安
1. ビルドスクリプト（N02 / N03 / KEN_ALL → `dict.db`、`municipalities` 定数、地図パス JSON、`overrides.json`）
2. DB の初期化: `dict.db` の同梱コピーと版管理、`user.db` の作成・マイグレーション
3. 候補検索（他N件含む）と訪問入力フロー
4. 地図（react-native-svg + gesture-handler + reanimated。パン範囲制限・リセットボタン）と一覧、ボトムシート
5. 履歴の追記・編集・削除（ボトムシート内）
6. ライト／ダークのテーマ定義と地図パレット
7. JSON エクスポート／インポート（検証・重複判定・トランザクション）
8. テスト（候補検索の正規化、制覇判定クエリ、インポート検証）
9. アプリ設定（アプリ名 tokyo-49、applicationId、縦固定、署名鍵の用意）

## 11. リスク・要確認事項
- **駅の読みデータのライセンス**: N02 に読みが無く、補完データの利用条件を確認する必要がある。
- **施設名の命中率**: 辞書では引けないため、施設は常に手動選択になる。許容できるか運用で確認する。
- **23区の地図タップ**: 区が小さく密集するため、ズーム初期表示・リセットボタン・一覧タブで補う。
- **データ消失**: バックアップ対策なしで、エクスポートも隠し導線のため、アンインストールや端末故障でデータが失われる。引き継ぎ前のエクスポート忘れに注意。
- **誤削除**: 削除は確認・Undoなしで即時実行され、復元できない。誤操作が気になる場合は、スナックバーでのUndoを後から追加できる。
- **APKの更新**: applicationId と署名鍵が変わると上書きインストールできず、データも引き継げない。署名鍵は必ず保管する。
